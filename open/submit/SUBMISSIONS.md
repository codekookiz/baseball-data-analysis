## ⚠️⚠️⚠️ 중요 — v1~v10 전체 규정 위반 소지 발견 및 v11 긴급 수정 (2026-08-09)

**문제**: `script.py`의 `predict()` 함수가 bias-fix를 이렇게 계산하고 있었다:
```python
shift = art["expected_rate_2025"] - pred.mean()   # pred = 지금 추론 중인 실제 평가 배치 전체
pred = np.clip(pred + shift, 1e-4, 1 - 1e-4)
```
`pred.mean()`이 **지금 추론 중인 실제 평가 데이터(24.5만 행) 자체의 평균**이다. 즉 모든 행의
예측값을 "이 평가 데이터 전체가 실제로 평균 몇 점이 나왔는지"에 맞춰 보정하고 있었다.

**규정 위반 근거**: 대회 규칙(추론 코드의 평가 데이터 예측 원칙, 4번 및 FAQ 하단에서 재차 강조):
> "평가 데이터의 다른 행이나 전체 평가 데이터의 분포를 이용해 특정 행의 예측값을 보정하거나
> 생성하는 방식은 정상적인 추론 절차로 인정되지 않습니다."

이건 정확히 그 사례에 해당한다 — **v1부터 v10까지 제출한 모든 버전이 이 문제를 갖고 있었다.**
실격 사유("규칙을 준수하지 않은 제출이 확인되는 경우, 규정에 따라 실격에 해당할 수 있습니다")에
해당할 수 있고, 100위 이내 진출 시 코드 검증(2차 평가) 단계에서 바로 드러날 문제였다.

**부수적 시사점**: 이게 지금까지 로컬 val 점수보다 실제 LB 점수가 계속 더 높게 나온 이유 중
하나였을 가능성이 있다 — 실제 정답 분포 정보가 (의도치 않게) 새어 들어가서 자동 보정되고
있었던 셈이다.

**수정 (v11)**: `train_final.py`에서 OOF 메타 예측(전부 train 데이터 기준)의 평균을 이용해
`bias_shift`를 **학습 시점에 한 번만** 계산해서 상수로 저장. `script.py`의 `predict()`는
이제 이 고정 상수를 더하기만 하고, 추론 중인 배치(X)는 전혀 참조하지 않는다.
```python
pred = np.clip(pred + art["bias_shift"], 1e-4, 1 - 1e-4)   # bias_shift: 학습 시 계산된 상수
```

**예상**: 점수가 떨어질 수 있다 (그동안 받던 부정 이득이 빠지는 것이므로) — 그래도 규정 준수가
최우선이라 판단하고 진행. v11 결과가 나오면 이게 실제로 얼마나 영향을 줬는지 확인 가능.

## R&D 노트 — LGB 변형(num_leaves=63) 추가: 기각 (2026-08-08)

**아이디어**: CatBoost에서 "depth8 대신이 아니라 depth6를 추가"하는 다양성 패턴(v9)이 통했으니,
같은 아이디어를 LightGBM에도 적용 — 기존 LGB(num_leaves=31)에 LGB(num_leaves=63, max_depth=9,
다른 시드)를 5번째 모델로 추가.

**결과** (raw brier, 4-way(v9) vs 5-way(+LGB63)):
```
        4-way(v9, 현재)  5-way(+LGB63)   승자
2022    0.243545         0.243557        4-way
2023    0.252995         0.253037        4-way
2024    0.247877         0.247864        5-way
```
**1/3만 승 — 기각. v9(4-way) 그대로 유지.**

**해석**: CatBoost의 "용량 변형 추가가 통하는" 패턴이 모델 계열마다 다른 것으로 보인다 — CatBoost는
ordered boosting 등 LGB/XGB와 근본적으로 다른 학습 방식이라 depth를 바꿔도 진짜 다른 오류 패턴이
나오는 반면, LGB는 같은 알고리즘 내에서 num_leaves만 바꾼 거라 상관관계가 높아 다양성 이득이 적은
것으로 추정. **"모델 다양성을 늘리는 것"과 "같은 모델의 하이퍼파라미터 변형을 늘리는 것"은 다른
이야기 — 후자는 일반적으로 통하지 않는다는 게 이번 두 사례(R21 CatBoost 자체 튜닝 기각, R23)로
재확인됨.**

**최종 확정 (오늘 세션)**: **v9 (895.03점, 211/601등)**가 최종 제출물.

**미완 실험 (중간에 중단, 결론 없음)**:
- **XGBoost dart 부스터 추가**: 알고리즘적 다양성 기대하고 시도했으나, dart는 조기종료가 잘 안 걸려서
  첫 fold조차 23분 넘게 안 끝나 중단. 다음에 시도한다면 `early_stopping_rounds`를 훨씬 크게 주거나
  `n_estimators`를 고정값으로 낮게 못박고 조기종료 없이 도는 방식으로 재시도 필요
- **RandomForest 추가**(배깅 계열 다양성): 다음날 재실행 완료.

**RandomForest 추가 결과** (raw brier, 4-way(v9) vs 5-way(+RF)):
```
        4-way(v9)    5-way(+RF)   승자
2022    0.243545     0.243586     4-way
2023    0.252995     0.252764     5-way
2024    0.247877     0.247916     4-way
```
**1/3만 승 — 기각.** 배깅 계열(RF)까지 안 먹혔다는 건, v9의 4-way(LGB+XGB+CatBoost×2)가 이미
이 문제에서 뽑아낼 수 있는 모델 다양성 이득을 거의 다 확보했다는 뜻으로 보인다. **"모델 추가"
방향은 여기서 종료 — 다음은 피처나 다른 구조적 접근이 필요.**

**채택.**

내장된 무작위성이 있어서, 외부 서브샘플링을 더하면 과도한 정규화가 되는 것으로 추정.

**v10 최종 구성**: LGB(서브샘플링 추가) + XGB(서브샘플링 추가) + CatBoost×2(기존 그대로 유지).

## R&D 노트 — bias_shift 참조 윈도우 확장(최근 2시즌 가중평균): 기각 (2026-08-09)

**아이디어**: v12는 `bias_shift`의 OOF 참조 평균을 "가장 최근 학습시즌(max_train_season) 1개"
행만으로 계산한다. 표본을 더 안정적으로 만들기 위해 최근 2개 시즌(예: 2023+2024)을
row-level 가중치(최근시즌 0.7 / 그 전 시즌 0.3)로 묶어 가중평균하면 더 낫지 않을까 검증.

**방법**: r35 스크립트를 확장(`r36_biasfix_window.py`)해 동일한 2021~2024 4-fold
walk-forward 체계에서 "v12(최근 1개 시즌)" vs "최근 2개 시즌 가중평균" 두 가지 bias_shift
기준을 raw brier로 직접 비교 (LGB 단일모델, fixed-shift 방식은 프로덕션과 동일).

**결과**:
```
2021: v12=0.247489  최근2개가중=0.248270  -> v12 승
2022: v12=0.243899  최근2개가중=0.243928  -> v12 승
2023: v12=0.252776  최근2개가중=0.252765  -> 최근2개가중 승 (사실상 동률, 노이즈 수준)
2024: v12=0.247851  최근2개가중=0.247969  -> v12 승
```
최근2개가중이 이긴 fold: 1/4 (그마저도 차이 0.000011로 노이즈 수준).

**결론**: 기각. v12의 "최근 1개 시즌만" 기준이 4-fold 중 3승으로 명확히 우세하고, 유일하게
진 fold도 개선폭이 무의미. 참조 윈도우를 넓히는 방향은 신호가 없음 — 표본을 더 안정화하는
효과보다 시즌 드리프트를 다시 섞어 넣는 효과가 더 큰 것으로 보임(v11 버그와 같은 방향의
리스크). v12 그대로 유지, 제출하지 않음.

## R&D 노트 — bias_shift 크기(alpha shrinkage) 스윕: 상충 신호, 기각 (2026-08-09)

**아이디어**: v12는 계산된 `bias_shift`를 100%(alpha=1.0) 그대로 더한다. 이 크기 자체가
최적인지, 줄이거나(shrinkage) 늘리는 게 더 나은지 `r37_shift_shrinkage.py`로 검증
(alpha ∈ {0, 0.5, 0.75, 1.0, 1.25, 1.5}, 동일 2021~2024 4-fold 체계, LGB 단일모델).

**결과** (raw brier, 작을수록 좋음):
```
              a=0.0     a=0.5     a=0.75    a=1.0(v12) a=1.25    a=1.5
2021(train2시즌) 0.245672  0.246292  0.246818  0.247489   0.248303  0.249261  -> a=0 최선
2022(train3시즌) 0.243536  0.243656  0.243762  0.243899   0.244067  0.244265  -> a=0 최선
2023(train4시즌) 0.253081  0.252899  0.252830  0.252776   0.252736  0.252711  -> a=1.5 최선(정반대!)
2024(train5시즌) 0.247905  0.247851  0.247844  0.247851   0.247872  0.247906  -> a=0.75, 근데 0.5~1.25 거의 평탄
평균:            0.247549  0.247674  0.247814  0.248004   0.248244  0.248536  -> a=0.0 최선
```

**해석**: 단순 평균은 alpha=0.0(보정 없음)이 가장 낮지만, fold별 최적값이 완전히 상충한다
(2021·2022는 "약하게", 2023은 "강하게" 보정하라고 정반대로 말함). 평균이 alpha=0쪽으로
쏠린 건 2021 fold의 변동폭(0.245672~0.249261, 학습 시즌 2개뿐이라 추세선이 가장 불안정)이
유독 크기 때문 — 이건 프로덕션(학습 시즌 6개)과 가장 안 닮은 fold다. 프로덕션과 가장 유사한
학습 시즌 5개짜리 2024 fold는 alpha 변화에 거의 무감(0.247844~0.247906, 4번째 소수자리
차이)해서, 애초에 alpha를 바꿀 근거가 약하다.

**결론**: 기각, v12(alpha=1.0) 유지. v12를 채택했던 기준("3/4 fold 이상 일관된 방향")을
충족하지 못함 — fold마다 정반대 방향을 가리키는 건 진짜 신호가 아니라 학습 시즌 수가 적은
초기 fold의 노이즈일 가능성이 크다고 판단. (참고: 이 실험은 "fold별로 다른 방법/파라미터를
적용하면 어떨까"라는 질문에서 나온 실험이었는데, 결과 자체가 왜 그게 위험한지 보여주는
사례가 됐다 — fold마다 정반대의 "최적값"이 나온다는 건 각 fold에 맞춰 사후에 골라 끼우는
방식이 실전(2025, 정답을 미리 알 수 없는 단일 fold)에서는 그대로 노이즈 과적합으로
이어질 수 있다는 뜻.)

**후기 (v13에서 실제로 제출)**: 로컬 근거는 약했지만, 일일 제출 기회가 매일 5개로 초기화된다는
점을 감안해 "애매해도 남은 기회를 쓰는 게 낫다"는 판단으로 alpha=0.75(가장 프로덕션과 닮은
2024 fold가 근소하게 선호했던 값)를 v13으로 실전 검증하기로 함. 아래 v13 항목 참고.
